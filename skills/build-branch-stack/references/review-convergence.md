# Review Convergence

Record epoch/design/mechanism/native owner in design checkpoint. Material owner,
state-model, dependency strategy, mechanism or slice-boundary change starts new
epoch with prior failure class and reason new design removes it. Identity/counts
persist across designs: family = invariant/runtime owner/supported path/failure.
Only reproduced or binding-proof material findings authorize edits; static
plausibility is advisory. Prefer root-cause removal/simplification over guards.

Before broader design record demonstrated failure, native owner, deletion option,
one invariant versus separable outcomes, harness footprint and patch removal
condition. Reject unnecessary state owners/async boundaries/patches/extensions.

| Trigger | Required continuation |
| --- | --- |
| New family/design/verification failures in any two discovery passes | Architecture reassessment before more incremental edits |
| Same underlying failure in two epochs | No third mechanism variation |
| Two accepted family fix cycles | No third local variation; autonomous continuation decision |

Apply `orchestration-triage-ledger-protocol.md` for trigger precedence, alternatives,
recorded decisions and one-cycle authorization. Compare removal/simplification,
native ownership, replacement/upgrade, narrow dependency correction or prerequisite
split by surface/ownership/rollback/check cost/maintenance. Amend checkpoint/plan
and continue viable in-scope designs. Ask only if all viable options cross caller
authority; block only affected chain when every local option violates hard constraints.

Use `code-review-loop.md` for the five completed three-reviewer discovery-pass cap,
non-counting closure/retry/repair/mappings, persistent counts and post-cap remediation/
verification/push/closure. No pass 6; capped review-stage handoff and separate human
release disposition preserve automated status. Use numbered passes, never predict
final/last/closing. Reuse proven equivalent checks; keep harnesses proportionate.
