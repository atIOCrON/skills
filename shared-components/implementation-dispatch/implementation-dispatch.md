# Implementation Dispatch

Apply `orchestration-runtime.md` for provider selection, persistent owner/chain
creation, IDs/names, leases, messaging and recovery. Use same owner for fixes,
amendments and invalidated evidence; availability does not authorize provider swap.

Render `implementation-dispatch-plan-invocation.md` with all assignment fields and
absolute bundled paths to plan-implement, from-reviewed-plan-to-git-handoff,
implementation-readiness, orchestration-plans-layout and operational-records.
Owner reads them and owns full implementation/check/trim/correctness/closure route;
complex work needs analysis and checkpoint before editing. Register ID/lease before
substantial work. Coordinator retains canonical state/moves/accepted refs/restacks/
publication; authoring lease names source/expected remote-or-absence/operation/return.
Return lease before acceptance. Post-acceptance fixes use isolated checkout at new
pin; coordinator installs/pushes before owner resumes reviews on confirmed remote.

Render `implementation-dispatch-fix-request.md` for same-ID follow-ups after execution
check. Batch accepted finding/family IDs, evidence class/supported path/proof, pins,
owned scope and focused checks; owner independently confirms or returns to triage.
Provisional fixes remain isolated/uncommitted until three-way reconciliation. New
commits never amend reviewed/published ones. Retain counts/originating-session
closure; no speculative refactor/shim/fallback/unrelated cleanup. Return ownership
expansion with exact paths/reasons for in-scope decision. Real unavailability alone
permits runtime-governed replacement preserving history.

Import early verified-candidate and final completion handoffs promptly under
orchestration-final-handoff and operational-records, including operator data.
Report original worker completion separately from accepted/current coverage/release
readiness; handoff grants no release publication authority.
